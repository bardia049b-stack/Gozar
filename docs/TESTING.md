# ماتریس تست و آنچه واقعاً اثبات شده است

این سند دقیقاً می‌گوید چه چیزی روی GitHub Actions اجرا می‌شود، چه چیزی را ثابت
می‌کند و چه چیزی **ثابت نشده** است. هدف این است که هیچ قابلیتی بدون دلیل
«پایدار» نامیده نشود.

## ۱. روی هر push — `Test All Platforms`

| Job | محیط | چه چیزی را ثابت می‌کند |
|---|---|---|
| `linux` | ubuntu-latest | `go vet ./...`، کل `go test ./...`، تست‌های جداشدهٔ UDP/WARP/WebRTC/گیم/geo، سیاست تنظیمات ایران |
| `windows` | windows-latest | همان تست‌ها + WFP؛ ساخت فایل اجرایی با پسوند `.exe` |
| `macos` | macos-15 | همان تست‌ها + PF |
| `android` | ubuntu + SDK | `:core:test`، `:app:testDebugUnitTest`، ساخت APK دیباگ |
| `openwrt` | ubuntu + Docker | کراس‌کامپایل، ساخت ipk، نصب در rootfs رسمی OpenWrt و اجرای واقعی `init.d` |
| `bypass` | ubuntu | تست‌های DPI، tunnel، dnsproxy، warp |
| `dpi-toxiproxy` | ubuntu + Docker | اختناق واقعی شبکه با toxiproxy (تأخیر، قطع، پهنای باند) |
| `flutter` | ubuntu + Flutter 3.24.5 | `flutter analyze` و `flutter test` (رابط کاربری، کلیدهای Advanced، دکمهٔ اسکن WARP) |

## ۲. روی هر push — `Hardening`

- ماتریس Go روی `linux/amd64`, `linux/arm64`, `windows/amd64`, `darwin/arm64`
- `reproducible-core`: دو بار ساخت و مقایسهٔ بایت‌به‌بایت خروجی

## ۳. پایداری طولانی — `Soak`

- روی هر push: **۵ دقیقه** بار واقعی.
- زمان‌بندی هفتگی: **۱۵ دقیقه**.
- دستی: تا **۴ مرحلهٔ ۳۵۰ دقیقه‌ای ≈ ۲۳ ساعت و ۲۰ دقیقه** (سقف هر job در
  GitHub شش ساعت است، برای همین ۲۴ ساعت به‌صورت مرحله‌ای اجرا می‌شود).

```
gh workflow run Soak --ref main -f minutes=350 -f stages=4
```

بار کاری داخل soak:

- یک اتصال HTTP/2 CONNECT واقعی با keep-alive (۱۶ کیلوبایت رفت‌وبرگشت، ~۵۰ بار
  در ثانیه) از میان استک شبکهٔ کاربری.
- یک جریان UDP روی پورت ۳۰۷۴ از میان QUIC + MASQUE واقعی (mock WARP).
- هر یک دقیقه یک **قطعی واقعی پروکسی** (بستن اتصال‌ها و listener) تا failover
  زیر بار آزمایش شود.
- سنجش کف heap پس از GC اجباری، تعداد goroutine و CPU.

نتیجهٔ اندازه‌گیری‌شده روی **GitHub Actions** (run 41982484402، کامیت 942dde5):

| شاخص | مقدار |
|---|---|
| مدت | ۵ دقیقه و ۳ ثانیه |
| TCP | **۱۴۰۷۷ از ۱۴۰۷۸ = ۹۹٫۹۹٪** |
| UDP | **۱۱۹۷ از ۱۱۹۷ = ۱۰٪** |
| قطعی پروکسی | ۴ بار تزریق شد |
| کف heap پس از GC | ۱٫۴ تا ۲٫۶ مگابایت — **ثابت، بدون رشد** |
| goroutine | ۴۷ تا ۴۸ در طول اجرا — **ثابت** |
| CPU | ۲٫۴٪ یک هسته |
| حجم جابه‌جاشده | ۲۳۲ مگابایت پایین / ۲۳۲ مگابایت بالا |

در اولین قطعی فقط **یک** جریان در حال پرواز از دست رفت و اتصال بعدی فوراً روی
پروکسی پشتیبان نشست؛ UDP اصلاً تحت تأثیر قرار نگرفت. اجرای محلی ۳ دقیقه‌ای هم
۸۳۴۹/۸۳۴۹ TCP و ۷۱/۷۱۸ UDP با کف heap ثابت ۲٫۰–۲٫۱ مگابایت داد.

> این تست یک باگ واقعی پیدا و رفع کرد: نگاشت‌های UDP بیکار هرگز منقضی نمی‌شدند
> و در هر دقیقه حدود ۲۶۰ goroutine نشت می‌کرد. حالا مثل NAT پس از ۳۰ ثانیه
> منقضی می‌شوند (`TestIdleUDPFlowsExpire`).

## ۴. بعد از انتشار — `Verify Release`

روی خودِ فایل‌هایی که کاربر دانلود می‌کند اجرا می‌شود، نه خروجی workspace ساخت:

1. اثرانگشت کلید عمومی منتشرشده با کلید رسمی Gozar مقایسه می‌شود.
2. `SHA256SUMS.txt.sig` و تک‌تک `.sig`ها بررسی می‌شوند.
3. `sha256sum -c` روی همهٔ فایل‌ها.
4. بستهٔ `.deb` روی Debian تمیز نصب می‌شود و `gozar-core --version` اجرا می‌شود.
5. محتوای `.ipk` (باینری + اسکریپت init) بررسی می‌شود.
6. گواهی امضای APK با apksigner بررسی می‌شود.
7. **اتصال زنده**: فقط اگر secretهای `GOZAR_TEST_EMAIL` و `GOZAR_TEST_PASSWORD`
   تنظیم شده باشند؛ در غیر این صورت صریحاً `NOT PERFORMED` گزارش می‌شود.

## ۵. آنچه اثبات **نشده** است (صادقانه)

| مورد | وضعیت |
|---|---|
| اسکن WARP روی اینترنت آزاد واقعی | در CI فقط با mock انجام می‌شود؛ الگوریتم و handshake واقعی‌اند، ولی reachability واقعیِ endpointها اثبات نشده |
| عبور از فیلترینگ واقعی یک کشور | toxiproxy اختناق شبکه را شبیه‌سازی می‌کند، نه DPI واقعی یک اپراتور |
| نصب روی دستگاه واقعی کاربر (ویندوز/مک/اندروید/روتر) | فقط نصب در کانتینر و build واقعی انجام شده؛ نصب دستی روی دستگاه انجام نشده |
| soak کامل ۲۴ ساعته | workflow آماده و روی هر push سبز است؛ soak اجراشده ۵ دقیقه‌ای بود، نه ۲۴ ساعته |
| مسیرهای Advanced روی اندروید | پیاده‌سازی نشده؛ هستهٔ اندروید جداست |
| Kill switch در سطح سیستم‌عامل روی دسکتاپ | فقط در سطح مسیر/فایروالِ خودِ اپ؛ تست OS-level انجام نشده |
| احراز هویت HTTP proxy روی اندروید | `ProxyInfo.buildDirectProxy` از username/password پشتیبانی نمی‌کند؛ محدودیت باز |
| `bypass.Validate()` | فعلاً no-op است؛ هر ترکیبی از کلیدها «معتبر» تلقی می‌شود |
| کلیدهای `tls_fragment`, `padding`, `jitter`, `keep_alive_tuning`, `non_standard_ports` | 프리미تیوهای آن‌ها (`FragmentConn`, `Pad`, `Jitter`) پیاده‌سازی و در برابر DPI شبیه‌سازی‌شده تست شده‌اند، ولی **به تونل وصل نشده‌اند**؛ روشن کردنشان امروز اثری روی ترافیک واقعی ندارد |
| کلیدهای `utls`, `h2_multiplex`, `doh_fallback`, `chain_socks5` | این رفتارها همیشه فعال‌اند (اثرانگشت uTLS، pool کردن HTTP/2، جانشین DoH، زنجیرهٔ SOCKS5/HTTP) و کلیدشان صرفاً وضعیت را گزارش می‌کند |
| گیم UDP روی اندروید | مسیر UDP جدید فقط دسکتاپ است |

هر مورد بالا تا وقتی واقعاً انجام نشده، در یادداشت انتشار هم «انجام‌نشده»
می‌ماند.
