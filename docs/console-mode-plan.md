# حالت کنسول در Gozar — طرح فنی (تحقیق، بدون پیاده‌سازی)

## ۱. واقعیت‌های خود کنسول‌ها

| کنسول | proxy دستی؟ | تنظیمات مرتبط | پورت‌های رسمی |
|---|---|---|---|
| PS5 | بله، فقط HTTP/HTTPS (آدرس + پورت، **بدون فیلد یوزر/پس**) | Settings → Network → Set Up Internet Connection → Advanced → Proxy Server = Use | TCP 80/443/3478/3479/3480، UDP 3478/3479، UDP 49152–65535 |
| PS4 | بله، همان (Custom setup) | Settings → Network → Set Up Internet Connection → Custom | همان |
| Xbox One / Series | **خیر** (اپدیت: Advanced settings فقط IP/DNS/MAC/port/QoS دارد) | فقط Gateway و DNS دستی | UDP/TCP 53 و 3074، UDP 88/500/3544/4500، TCP 80 |
| Switch | ندارد | — | — |

نتیجهٔ مستقیم:
- PS با proxy کار می‌کند، ولی proxy فقط **TCP** را حمل می‌کند؛ ترافیک بازی (UDP) از آن رد نمی‌شود.
- Xbox اصلاً proxy ندارد؛ تنها راه، **gateway/NAT** است (کارت شبکهٔ کامپیوتر یا هات‌اسپات، نه پراکسی).

## ۲. محدودیت خود Gozar (مهم‌ترین یافته)

خروجی تونل ما MASQUE روی شبکهٔ Mozilla است و فقط CONNECT به **TCP 80/443/8080/8443** را قبول می‌کند:

- استور، آپدیت، لاگین PSN/Xbox Live، حتی ویدیو → **کار می‌کند**.
- مولتی‌پلیر، پارتی، NAT type، ترافیک UDP 3478/3074/88/500/4500 → **کار نمی‌کند**، حتی با gateway کامل.
- پس هر پیاده‌سازی تا وقتی خروجی UDP-capable (WireGuard/hysteria) اضافه نشود، «نیمه‌کاره ولی صادق» است.

## ۳. سه مسیر پیاده‌سازی

### A. اندروید، بدون روت — «حالت کنسول» با پراکسی
1. `FoxLink.prepare()` فعلی سه شنوندهٔ لوپ‌بک می‌سازد؛ حالت کنسول یک شنوندهٔ **اضافی** روی IP تترینگ (`192.168.43.1` / `192.168.232.1` / `192.168.208.1`) می‌سازد.
2. تشخیص IP: شمارش `NetworkInterface`، انتخاب آدرس خصوصی غیر از tun و غیر از آدرس کلاینت Wi-Fi؛ نتیجه به کاربر نشان داده و قابل اصلاح دستی.
3. PS5/PS4: `Advanced → Proxy = Use` + همان IP و پورت. بدون یوزر/پس چون کنسول فیلد ندارد.
4. DNS: PS اجازهٔ DNS دستی می‌دهد؛ یک resolver روی پورت 53 همان اینترفیس (اگر bind نشد، حالت «DNS خودکار» با هشدار نشت).
5. محدودیت صادقانه در UI: «استور/آپدیت/لاگین بله، آنلاین بازی خیر».

### B. اندروید با روت — gateway کامل
همان دستورهای شناخته‌شده:
```
iptables -t nat -I POSTROUTING -s 192.168.43.0/24 -o tun0 -j MASQUERADE
ip rule add from 192.168.43.0/24 lookup 61
ip route add default dev tun0 table 61
```
با FoxStack فعلی (که IPv6 را drop می‌کند) سازگار است، ولی UDP باز هم از upstream رد می‌شود. ارزش واقعی‌اش فقط وقتی است که خروجی UDP-capable داشته باشیم.

### C. دسکتاپ — این همان راهی است که Xbox هم جواب می‌دهد
- **ویندوز:** ICS روی آداپتور TUN گوزار → پورت اترنت (یا Mobile hotspot با source = TUN). Xbox با IP/DNS خودکار به آن وصل می‌شود؛ PS هم می‌تواند proxy بزند یا همین gateway را بگیرد. ساب‌نت ICS = `192.168.137.0/24`، IP گیت‌وی `192.168.137.1`.
- **لینوکس:** `nmcli` هات‌اسپات + `net.ipv4.ip_forward=1` + `nft` masquerade از `gozar0` به ساب‌نت هات‌اسپات.
- **مک:** Internet Sharing با source = اینترفیس tun؛ ناپایدارتر، نیاز به تست واقعی.
- مزیت: یک دکمه در Gozar که این قوانین را می‌سازد و در stop پاک می‌کند؛ MTU را ۱۴۰۰ اعلام کن (MTU تون ما ۱۴۰۰ است) تا کنسول بسته‌های بزرگ نفرستد.

## ۴. طراحی امنیتی (چون پورت روی LAN باز می‌شود)

- حالت کنسول **پیش‌فرض خاموش** و فقط با انتخاب کاربر روشن می‌شود؛ فقط تا وقتی VPN وصل است.
- شنونده فقط به IP تترینگ bind می‌شود، نه `0.0.0.0`؛ در حالت Wi-Fi کلاینت هیچ شنونده‌ای روی LAN باز نمی‌شود.
- allowlist ساب‌نت + (در صورت امکان) پین کردن MAC کنسول از جدول ARP.
- سقف اتصال، نرخ‌محدودسازی، تایم‌اوت بیکاری، لاگ «چه کسی وصل است» و دکمهٔ قطع فوری.
- SOCKS5 همان احراز هویت قبلی را نگه می‌دارد؛ HTTP بدون auth است چون کنسول فیلد ندارد — این را در UI صریح بنویس.
- پورت‌های لوپ‌بک فعلی دست‌نخورده می‌مانند.

## ۵. پیشنهاد ترتیب کار

1. دسکتاپ: gateway (ویندوز ICS + لینوکس nft) — تنها راه Xbox، و PS هم بدون تغییر روی کنسول کار می‌کند. → بیشترین ارزش.
2. اندروید: حالت کنسول پراکسی برای PS (بدون روت).
3. بعدی: خروجی UDP-capable تا مولتی‌پلیر واقعی ممکن شود (پروژهٔ جدا).
