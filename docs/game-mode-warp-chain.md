# Game Mode — عبور کامل UDP با زنجیرهٔ دو مرحله‌ای (WARP داخل MASQUE)

## چرا این راه جواب می‌دهد

رلهٔ موزیلا یک **پروکسی با لیست سفید پورت مقصد** است؛ پورت‌های ۸۰/۴۴۳/۸۰۸۰/۸۴۴۳ و ۳۴۷۸ باز است و بقیه `502`. Xbox روی ۳۰۷۴/۸۸/۵۰۰/۴۵۰۰ است و هیچ‌وقت باز نمی‌شود.

اما اگر پروکسی فقط **پورت** را چک می‌کند، پس کافی است به یک مقصد مجاز وصل شویم که خودش **هر UDP** را قبول کند. Cloudflare WARP دقیقاً همین است: یک VPN کامل روی **UDP/TCP 443** با SNI `consumer-masque.cloudflareclient.com`.

```
بازی/کنسول
   ↓
Gozar (TUN) ──► Mozilla MASQUE (پورت مجاز 443)
                   ↓  CONNECT 162.159.198.2:443   یا  CONNECT-UDP :443
                Cloudflare WARP (connect-ip)
                   ↓
                اینترنت با UDP بدون محدودیت پورت
```

## آنچه در سندباکس واقعاً اندازه‌گیری شد

| آزمون | نتیجه |
|---|---|
| TLS به `162.159.198.2:443` با SNI مصرف‌کنندهٔ WARP | ✅ `h2` / TLS 1.3 (پورت‌های ۵۰۰/۱۷۰۱/۴۵۰۰/۸۴۴۳ هم باز) |
| ثبت‌نام دستگاه MASQUE (کلید P-256) | ✅ حساب free، آدرس `172.16.0.2` گرفت |
| اجرای `usque` و ساخت تونل | ✅ `warp=on`، `loc=US`، `colo=SEA` |
| TCP از داخل تونل | ✅ `curl` از طریق SOCKS5 |
| **UDP دلخواه از داخل تونل** | ✅ STUN Binding Success روی `stun.l.google.com:19302` |
| مسیر دوم: `connect-ip` روی رلهٔ موزیلا | ❌ `404` (خود موزیلا پشتیبانی نمی‌کند) — لازم هم نیست |
| مسیر اول: `connect-udp` موزیلا به پورت ۴۴۳ | ✅ `200` (مجاز) |
| مسیر سوم: `CONNECT` سادهٔ TCP به پورت ۴۴۳ هر مقصد | ✅ `200` |

یعنی **هر سه قطعه آماده است** و فقط باید به هم وصل شوند.

## دو معماری قابل پیاده‌سازی

### A) h3 (UDP داخل UDP) — پیشنهادی برای اندروید
WARP روی QUIC/UDP 443 حرف می‌زند. برای عبور از موزیلا:
1. Gozar یک شنوندهٔ UDP محلی می‌سازد (مثلاً `127.0.0.1:51820`).
2. هر دیتاگرام آن را در **CONNECT-UDP موزیلا** به `162.159.198.2:443` می‌فرستد.
3. `usque` روی همان سوکت محلی، تونل WARP را می‌سازد.
4. داخل WARP یک SOCKS5 UDP-ASSOCIATE می‌گیریم؛ تمام UDP بازی از آن می‌رود.

مزیت: تونل WARP همان چیزی است که کلاینت رسمی استفاده می‌کند، پس پایدار. عیب: دو لایه QUIC → MTU مؤثر ~۱۲۰۰، تأخیر بالاتر.

### B) h2 (TCP داخل TCP) — ساده‌ترین برای دسکتاپ
WARP روی **HTTP/2 روی TCP 443** هم سرویس می‌دهد. Gozar همین حالا تونل TCP CONNECT دارد؛ پس بدون هیچ لایهٔ UDP جدید:
1. `CONNECT 162.159.198.2:443` از رلهٔ موزیلا.
2. داخلش `connect-ip` (RFC 9484) روی h2.
3. مسیردهی فقط برای UDP (و اختیاری TCP) بازی به این تونل.

مزیت: بدون کد UDP جدید، سازگار با معماری فعلی. عیب: TCP-in-TCP → جیتر برای بازی بیشتر.

## محدودیت‌هایی که باید صادقانه گفت

1. **NAT Type**: خروجی WARP یک CGNAT است؛ حتی با UDP کامل، Xbox ممکن است `Strict/NAT Type 3` بماند. بازی‌های P2P مشکل خواهند داشت، ولی Live/PSN، استور، آپدیت، پارتی و بخش بزرگی از بازی‌های سرور-محور کار می‌کند.
2. **Xbox بدون پراکسی**: کنسول باید از طریق گیت‌وی (ICS/هات‌اسپات) وصل شود، نه پراکسی. مسیر A/B هر دو با گیت‌وی سازگارند.
3. **زنجیرهٔ دو VPN** کار رایجی است ولی روی ToS موزیلا و Cloudflare لبه دارد؛ برای استفادهٔ شخصی و سبک نوشته شده، نه ترافیک انبوه.
4. **MTU**: باید ۱۲۴۰–۱۲۸۰ تنظیم شود و PMTU کار کند، وگرنه بسته‌های بزرگ بی‌صدا گم می‌شوند (همان چیزی که بازی را «قطع‌وصل» نشان می‌دهد).

## وضعیت فعلی تست

قطعه‌های ۱–۳ تأیید شده‌اند. اتصال نهایی (WARP از داخل تونل موزیلا) نیاز به یک **توکن تازه** دارد؛ login با محدودیت نرخ `429` مواجه شد و باید از IP دیگر یا بعد از چند دقیقه انجام شود.

## ۷. پیشرفت مهندسی (آزمون‌های همین نشست)

- ✅ کلاینت دستی HTTP/3 با Extended-CONNECT + دیتاگرام نوشته شد (`udp-probe/tunnel.go`) و **تونل UDP واقعی باز می‌کند**.
- ✅ با یک پروکسی محلی، دست‌دادن QUIC **داخل** تونل شروع شد؛ تنها مانع باقی‌مانده **اندازهٔ بسته** است:
  `DATAGRAM frame too large` و سپس timeout.
- 🔧 راه‌حل مشخص: محدود کردن بستهٔ اولیهٔ QUIC داخلی (`InitialPacketSize ≈ 1000`) و کشف PMTU غیرفعال، به‌علاوهٔ MTU ۱۲۴۰ برای لایهٔ بیرونی. همان چیزی که برای تونل‌های تودرتو استاندارد است.
- ⏳ اتصال به WARP از داخل تونل موزیلا هنوز اجرا نشده: login با `429 Too Many Requests` محدود شد (محدودیت نرخ روی IP سندباکس).
